## Повтор после следующего улучшения

1. `node scripts/verify-ux.mjs change-name` — типы, все UI journeys и регрессия, render check. Логи: .orca/ux-evidence/change-name.
2. Подготовить fixture: `node scripts/ux-e2e/run.mjs --prepare`.
3. Если работает screenshot RPC: скрыть окно через UI, `node scripts/ux-e2e/run.mjs --existing`.
4. При runtime_timeout использовать CUA: `--existing --configure S01-1`, выполнить действия из вывода в тестовой панели, нажать E2E capture, `--existing --check-case S01-1`. Повторить все S01-1 … S12-2. Для S08-2 сделать именно двойной клик во время задержанного ответа. Для S01-2 дополнительно reload панели после выбора старого прогона.
5. Выгрузить fixture через plugin dev unload и открыть основную панель. Не загружать весь рабочий репозиторий в dev watch: SQLite shm вызывает цикл перезагрузок.

## Ограничения доказательств

Native-набор проверяет UX/IPC с управляемым worker, не реальный LLM, авторизацию провайдеров, падение ОС или process supervision production coordinator. Для runtime уже есть отдельные тесты; это не основание заявлять такие e2e пройденными. Keyboard/focus на всех платформах не исследованы. Оценка вариантов — отдельный критический проход автора, без независимого внешнего эксперта и пользовательского исследования.

Для 0.2.1 проверены история, перенос настроек и панель шириной 320 и 480 пикселей на обоих языках. Сценарий клавиатуры прошёл в установленном редакторе. [Изменения в 0.2.1](../release-0.2.1.md)

## Версия 0.4.0 · 26 ноября 2026

В тестовой панели Orca проверены сохранение шаблона, повторное открытие в другом проекте, подстановка параметров, репетиция ошибки до старта, выбор базового прогона, сравнение отчётов и переход в обе сессии при передаче шага. Тест обработчиков панели использует настоящий временный Git-репозиторий и проверяет содержимое индекса после приёмки. В консольном тесте отдельный процесс создаёт файл в рабочей копии, после чего команды diff и accept переносят проверенный файл в исходный проект.

Шаблон «аудит → улучшения → независимая проверка» выполнен через консоль в Jarvis и Agent Pipeline. Область проверки ограничена первыми 15 строками README. В обоих прогонах с Codex три шага сохранили отчёты и завершили проверку pwd с кодом 0. В отдельных прогонах с Pi/profm после успешного аудита на втором шаге соединение закрылось с UND_ERR_SOCKET.
