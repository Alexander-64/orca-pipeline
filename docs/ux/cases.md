# Пользовательские e2e-кейсы

Среда: Orca, установленный Agent Pipeline, тестовый проект, сценарий из двух независимых шагов и одного join. Для сбоев нужен управляемый тестовый исполнитель. После каждого улучшения запускать весь набор; фиксировать фактический слой проверки. Не запускать реальные команды пользователя ради smoke-теста.

Каждая строка содержит два отдельных тест-кейса. Во всех: нет ошибок renderer, выбранный прогон не меняется от фонового события.

| Сценарий | E2E-1: действия → результат | E2E-2: действия → результат |
|---|---|---|
| S01 Вход / история | открыть панель, выбрать старый прогон → верное имя, проект, параметры | перезапустить панель → выбранный ID восстановлен |
| S02 Новый проект / черновик | Новый прогон, выбрать проект, ввести цель → можно перейти к шагам | открыть старый, затем Новый → сохранён свой черновик, старый неизменён |
| S03 Планирование | указать цель, Составить YAML, дождаться результата → граф валиден | получить невалидный ответ planner → прошлый граф сохранён, ошибка видна |
| S04 Граф и зависимости | добавить параллельный и дочерний шаг → видны волны и входы join | попытаться создать цикл → запрещено; удалить вход → YAML валиден |
| S05 Агент, резерв, модель | выбрать модель и effort из каталога → сохранены в YAML | поменять агента → несовместимый model/effort сброшен, резерв не дублируется |
| S06 Запуск | валидный черновик, Запустить → один прогон, параметры readonly | ограничить путь и выбрать отдельный workspace → до запуска видна причина запрета |
| S07 Наблюдение | завершить один шаг → успехи выросли, активный шаг выбран | завершить другой ошибкой → ошибка не увеличивает долю успехов |
| S08 Восстановление | получить unconfirmed receipt → понятное объяснение, обычный resume недоступен | Разберись и продолжи, два клика → один запрос, итог диагностики, вкладка сохранена |
| S09 Ответ / подтверждение | вопрос агента, ответить → ответ связан с question ID | сетевой timeout, повтор ответа → прежний message ID, gate не подтверждён автоматически |
| S10 Результаты | выбрать завершённый прогон → финальные и пошаговые результаты | выбрать незавершённый → явно промежуточный результат, Открыть шаг ведёт к нему |
| S11 Задачи / Beads | открыть Задачи при выключенном Beads → встроенные задачи доступны | включить Beads без bd → диагностика, встроенные задачи работают |
| S12 Метрики | открыть Метрики → агрегаты выбранного проекта | завершить шаг, обновить данные → агрегаты согласованы с задачами |

## Автоматизированный слой

- src/panel.test.tsx: история, запуск, readonly, новый черновик, вопросы, восстановление, результат, DAG.
- src/editor.test.tsx: граф, циклы, модели, резерв, шаблоны, YAML.
- src/planner.ui.test.tsx: валидный/невалидный planner, сохранность ручных правок.
- src/beads.board.test.ts, src/metrics.test.ts: трекер и агрегаты.
- src/ux.journeys.test.tsx: новые сквозные пользовательские переходы S01/S07/S08/S10/S11/S12 через UI с контролируемым хостом.
- scripts/ux-e2e: 24 native-кейса; --configure/--check-case поддерживают CUA-драйвер при недоступном screenshot RPC.
- plugin check + plugin shot: настоящий renderer Orca, разные ширины; это render smoke, без заявления о полном browser/agent e2e.

Native e2e завершены через CUA: все S01-1 … S12-2 прошли с детерминированным worker; повтор открытия панели проверен дополнительно. Свидетельства и границы — в validation.md.

Оставшиеся проверки полного хостового процесса вне UX-набора: keyboard/focus на всех платформах, реальный LLM, восстановление после падения ОС. Их статус должен оставаться «не прогонялось», пока нет фактических свидетельств.
